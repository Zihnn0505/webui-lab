## 2. AI Summary

### 2.1 使用者角色
#### 買家
- 瀏覽與購買商品
- 參與團購活動
- 使用邀請碼取得優惠
- 查看訂單與付款狀態
- 接收通知與進行評價

#### 賣家 / Manager
- 管理商品與 SKU
- 管理庫存與價格
- 建立及管理團購活動
- 查看與處理訂單
- 管理退款與通知

### 2.2 Web / API 閘道
Web / API 閘道作為前端與後端服務之間的入口，負責統一處理系統安全與流量控制。

主要功能：
- 身份驗證
- API 限流
- 個資保護
- API 請求轉發

### 2.3 核心服務模組
核心服務模組負責平台主要的商業邏輯與資料處理。

- SKU 管理：負責商品的規格、庫存與價格管理。
- 成團條件：設定團購所需的人數或商品數量門檻。
- 限時倒數：管理團購活動的開始時間、結束時間與剩餘期限。
- 邀請碼：管理邀請碼、折扣以及相關使用規則。
- 訂單管理：處理訂單建立、付款、出貨及訂單狀態流轉。
- 庫存預扣：在使用者下單時預先保留庫存，避免多人同時購買造成超賣。
- 支付退款：串接第三方金流，處理付款、退款及交易狀態。
- 通知評價：負責發送訂單、團購等相關通知，以及收集使用者評價與回饋。

### 2.4 基礎服務
- 資料層：負責保存系統資料，並透過資料庫與快取提供資料存取功能。
- 第三方支付：透過金流 API 串接外部支付服務，處理付款與退款交易。
- 通知管道：透過 LINE、Email、簡訊等方式向使用者發送系統通知。

### 2.5 流程
```text
買家 / 賣家
     ↓
Web / API 閘道
     ↓
核心服務模組
     ↓
資料層 / 第三方支付 / 通知管道
```

## 4. APIs that may be used
- 登入與驗證相關 API
  - `POST /api/auth/register`：註冊新帳號並建立 session。
  - `POST /api/auth/login`：使用 Email / 使用者名稱登入。
  - `GET /api/auth/me`：檢查目前登入狀態並回傳使用者資訊。
  - `POST /api/auth/logout`：登出並清除 session。
  - `GET /api/auth/google`、`GET /api/auth/google/callback`：串接 Google OAuth 2.0，實現第三方登入。
- 團購商品相關 API
  - `GET /api/group-buys`：取得公開的團購商品列表。
  - `GET /api/group-buys/mine`：取得目前賣家自己的團購資料。
  - `POST /api/group-buys`：建立新團購商品。
  - `PUT /api/group-buys/:groupId`：更新已存在的團購資料。
  - `DELETE /api/group-buys/:groupId`：刪除團購商品。
  - `GET /api/group-buys/images/:imageName`：讀取團購圖片。
- 前端資料交換方式
  - 主要透過 `fetch()` 進行前後端資料交換，依照 HTTP method 送出 `GET`、`POST`、`PUT`、`DELETE` 請求。
  - 透過 Session Cookie 保持登入狀態，避免每次請求都重複驗證身份。
- 未來可能擴充的金流 / 通知 API
  - 支付 API（如 Stripe、ECPay 或 LINE Pay）：處理訂單付款、退款與交易狀態更新。
  - 通知 API（如 LINE Notify、Email SMTP、簡訊服務）：發送訂單通知、成團提醒與付款確認通知。
